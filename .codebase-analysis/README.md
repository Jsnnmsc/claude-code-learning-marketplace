# Codebase Analysis Results

This directory stores the analysis results generated by the codebase learning plugin commands.

## Directory Structure

Analysis files are organized by type and timestamp:

```
.codebase-analysis/
├── architecture-[timestamp].md    # Architecture analysis results
├── flow-[feature]-[timestamp].md  # Code flow tracing results
├── patterns-[timestamp].md        # Pattern detection results
└── concepts-[name]-[timestamp].md # Domain concept exploration results
```

## File Format

Each analysis file contains:
- **Analysis Type**: Architecture, Flow, Patterns, or Concepts
- **Date & Time**: When the analysis was performed
- **Scope**: What part of the codebase was analyzed
- **Detailed Findings**: Complete analysis from the AI agent
- **Code References**: Links to relevant files and line numbers
- **Diagrams**: Visual representations (Mermaid diagrams)
- **Related Topics**: Suggestions for further exploration

## Using Analysis Files

### View in Editor
Open any `.md` file in your preferred markdown editor or IDE to see:
- Formatted markdown with syntax highlighting
- Rendered Mermaid diagrams
- Clickable file path references
- Proper heading structure for easy navigation

### Search Across Analyses
```bash
# Find all analyses mentioning a specific topic
grep -r "authentication" .codebase-analysis/

# List all architecture analyses
ls .codebase-analysis/architecture-*.md

# Find specific patterns
grep -r "Factory pattern" .codebase-analysis/
```

### Share with Team
These markdown files can be:
- Committed to version control
- Shared via documentation platforms
- Used as reference documentation
- Included in wikis or knowledge bases

## Tips

1. **Open in Editor**: For the best viewing experience, open analysis files in your IDE or markdown editor
2. **Compare Results**: Keep multiple analyses to track how your understanding evolves
3. **Create Index**: Consider creating an index file linking to all analyses
4. **Regular Cleanup**: Remove outdated analyses to keep the directory manageable
5. **Version Control**: Add this directory to `.gitignore` if analyses are personal, or commit them if they're team documentation

## Git Ignore

By default, this directory is excluded from version control. If you want to commit analyses to your repository, remove `.codebase-analysis/` from your `.gitignore` file.
